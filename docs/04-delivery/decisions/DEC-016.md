# DEC-016 — Mecanismo de autenticación

**Estado:** APPROVED
**Fecha:** 2026-08-05

## Contexto

La decisión estaba planteada como «Auth.js estable o alternativa». La verificación del ecosistema en la fecha de aprobación resolvió la premisa: **Auth.js no está estable.**

| Paquete | Estado verificado el 2026-08-05 |
|---|---|
| `next-auth` v5 | En beta desde 2023-10-24; última beta `5.0.0-beta.32` del 2026-07-20 |
| `next-auth` latest | `4.24.15`, diseñado para Pages Router |
| `@auth/core` | `0.41.3`, aún 0.x |
| `lucia` | Deprecado oficialmente por su autor |
| `better-auth` | `1.6.26` estable; declara soporte de Next 16, React 19 y Prisma 7 |

Adoptar una beta de casi tres años en el camino crítico de autenticación de un sistema que gestiona dinero no es aceptable.

## Decisión

Se adopta **Better Auth 1.6.26** como mecanismo de autenticación y sesión.

- Autoalojado dentro del monolito, sin servicio externo ni dependencia de terceros en tiempo de ejecución. Coherente con DEC-001, que sitúa toda la infraestructura en el VPS.
- Persistencia en PostgreSQL mediante el adaptador de Prisma, sobre la misma base autoritativa.
- Las sesiones se almacenan en base de datos, no solo en cookie firmada, para poder revocarlas de inmediato.
- Better Auth resuelve identidad y sesión. **La autorización sigue siendo del dominio**: `packages/domain/src/rbac.ts` es la única fuente de decisión sobre permisos y scopes, y no se delega en la librería.

## Consecuencias

- Se añade `better-auth` como dependencia productiva.
- El modelo de datos incorpora sesiones, cuentas, verificación y factores MFA. La tabla `users` existente de P03 se conserva como identidad; Better Auth se acopla a ella.
- Un cambio futuro de proveedor afecta solo a la capa de infraestructura: el dominio no conoce la librería.
- Queda cerrado el bloqueo que impedía implementar autenticación productiva desde P01.
- Sustituye la premisa original de la decisión, que asumía Auth.js como opción por defecto.
