# ADR-010 — Better Auth para identidad y sesión, autorización en el dominio

**Estado:** ACCEPTED
**Versión:** 2.7
**Fecha:** 2026-08-05

## Contexto

DEC-016 estaba planteada como «Auth.js estable o alternativa». Al verificar el ecosistema el 2026-08-05, la premisa resultó falsa: `next-auth` v5 lleva en beta desde octubre de 2023, `@auth/core` sigue en 0.x, y `lucia` está deprecado. La única opción estable que declara soporte de Next 16, React 19 y Prisma 7 es Better Auth 1.6.26.

El sistema gestiona dinero y datos personales, y DEC-001 exige que todo corra en infraestructura propia.

## Decisión

Better Auth 1.6.26 resuelve **identidad y sesión**. La **autorización sigue en el dominio**.

La separación es deliberada:

- `packages/domain/src/rbac.ts` es la única fuente de decisión sobre permisos y scopes. No se delega en la librería ni se duplica en ella.
- La librería responde «quién eres»; el dominio responde «qué puedes hacer aquí».
- Las sesiones se persisten en PostgreSQL, no solo en cookie firmada, para poder revocarlas de inmediato.

## Consecuencias

- Cambiar de proveedor de autenticación afecta únicamente a `packages/infrastructure`. El dominio y sus pruebas no lo conocen.
- Las reglas de RBAC probadas en P03 siguen siendo la autoridad, sin reescribirse.
- El modelo de datos gana sesiones, cuentas, verificación y factores MFA, acoplados a la tabla `users` existente.
- Una vulnerabilidad en la librería compromete la sesión, no el modelo de permisos.
- Un cambio estructural aquí requiere nueva ADR y actualización de contratos.
